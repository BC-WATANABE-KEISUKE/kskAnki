## 総評

要件定義 (`REQUIREMENTS.md`) の**画面・機能の「見た目」は広くカバーされており、SwiftUIのビュー構成は素直で読みやすい**です。カードモデルの表現力（3種の表面タイプ、裏面詳細フィールド、13種の学習フィルター）も学習アプリとして良い設計方針だと思います。

一方で、現状は **「動くUIのプロトタイプ」であって、アプリとして成立していません**。理由は3つです。

1. **iOSアプリとしてビルドできない** — Xcodeプロジェクトもアプリターゲットも存在せず、`@main` がSPMライブラリターゲット内にあるため `swift test` はリンクエラーで失敗します（実測済み）。
2. **データが一切永続化されない** — `DeckStore` はメモリ上のみ。ADR-0001で採用を決めたSwiftDataのコードは1行もありません。アプリを再起動すると学習履歴もカードも全消失します。
3. **SRSエンジンが実際には使われていない** — `dueDate` を計算はしていますが、それを使って出題カードを選ぶ経路がどこにもありません。暗記アプリの中核価値が空洞化しています。

加えて、**UIに表示されている数値の一部が偽物**（ストリーク「3日連続」・本日「12/20枚」はハードコード定数）、**PhotosPickerが完全な空実装**（選択しても何も起きない）、**APIキーが平文でUserDefaultsに保存**といった、ユーザーに実害が出る問題があります。

「機能を増やす」より先に、**永続化・アプリターゲット・SRSの出題経路の3点を通す**ことを最優先に据えることを強く推奨します。

## 推奨対応ロードマップ

### フェーズ0: 土台を通す（これができるまで機能追加を止める）

1. Xcodeプロジェクト（またはSPMのapp target構成）を作成し、`@main` をアプリターゲットへ移す → `swift test` のリンクエラーも同時に解消 (BLK-01, BLK-02)
2. SwiftDataによる永続化を導入。`AnkiCard` / `AnkiDeck` / `Course` / `CourseFolder` を `@Model` 化 (BLK-03)
3. 学習セッションの結果が必ず保存される経路に統一 (BLK-04, BLK-05)
4. `swift-testing` (または XCTest) を導入し、`SpacedRepetitionScheduler` / `StudyFilterConfig` / cloze パーサ / CSV パーサの純粋ロジックにテストを書く (QA-01)

### フェーズ1: 中核価値を正す

5. `dueDate` ベースの「今日の復習」フィルターを追加し、SRSを実際に機能させる (SRS-01)
6. `easeFactor` の上限、`.doubtful` の間隔短縮、`isUnlearned` の判定基準など SM-2 の逸脱を修正 (SRS-02〜05)
7. カード編集時のデッキ破壊を修正 (ARC-02)
8. ストリーク・日次目標を実データから算出、または表示を一旦隠す (ARC-04)
9. PhotosPicker を実装し、画像をアプリコンテナに保存＋ローカル画像を描画できるようにする (UX-03, UX-04)

### フェーズ2: 品質を上げる

10. APIキーをKeychainへ移行、または未使用の設定項目ごと削除 (SEC-01)
11. 設定値（自動音声・Haptics・復習上限）を実際に配線 (ARC-05)
12. アクセシビリティ対応（VoiceOverラベル、Dynamic Type、ダークモード配色） (UX-05, UX-06, UX-08)
13. ネストScrollViewとDragGestureの競合を解消。「上スワイプ=△」の再設計 (UX-01, UX-02)
14. `.gitignore` に Swift/Xcode エントリを追加してから初回コミットする (QA-03)

## 良かった点

公平を期すため、評価できる点も明記します。

- **モデル層が `Sendable` / `Codable` / 値型で統一されている** — 永続化層を後から差し込みやすい素直な設計です。
- **`StudyFilterConfig.filterCards` が純粋関数** — ビューから独立しており、テストを書けばすぐ品質が担保できる状態にあります (`src/Models/StudyFilter.swift:71`)。
- **13種の学習フィルターと `description` の併記** — 学習者が条件を理解できるUIで、教育アプリとして良い配慮です。
- **`#if canImport(UIKit)` / `#if os(iOS)` による2環境ビルド互換の維持** — 要件4.2を満たしており、Mac上での高速な検証サイクルを実現しています。
- **ドキュメント駆動 (`CONTEXT.md` / `docs/adr/` / `.scratch/*/spec.md`) の運用** — 意思決定の追跡が可能で、レビューがしやすい状態でした。
